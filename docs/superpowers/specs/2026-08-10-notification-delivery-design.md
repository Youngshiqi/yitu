# 通知与投递记录设计

## 范围

任务四首先建立通知事实和渠道投递记录。通知由业务事件驱动，正文使用后端白名单模板渲染；本小任务不接入真实短信供应商，也不实现 SSE。

## 数据模型

- `notification_messages` 保存事件、接收人、模板编码、模板参数、渲染后的正文和逻辑状态。
- `notification_deliveries` 保存每个渠道的投递状态、重试次数、错误原因和时间。
- 同一个 `event_id + recipient_id + channel` 只能创建一条投递记录，重复消费只更新已有记录，不产生重复通知。

## 约束

- 接收人必须关联现有用户。
- 通知和投递记录均使用带时区时间。
- 渠道首期为 `IN_APP`、模拟 `SMS`；真实供应商留到后续任务。
- 数据库迁移编号使用 `0017`。
