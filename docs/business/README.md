# 业务规则导航与后续节点

本目录保存需要由运营人员确认、并最终落入结构化数据库规则的业务基线。这里的数字是驿途首版演示规则，不代表任何第三方快递公司的官方报价或承诺。

## 当前节点

- 已完成：阶段一工程基础、阶段二物流核心。
- 当前待开始：阶段三商业与履约可靠性。
- 当前业务规则：`pricing-rules.md`、`sla-rules.md`。
- 规则状态：`演示基线 / 待运营确认`，在规则确认前不得作为正式生产报价。

## 阶段三执行顺序

1. **3.1 计价**：建立价格规则版本、报价快照、费用明细和复重接口；先完成 `pricing-rules.md` 中的结构化字段。
2. **3.2 支付**：接入模拟支付、补差价、退款和支付幂等回调；支付只能消费报价快照，不能自行改价。
3. **3.3 SLA/ETA**：建立 SLA 规则版本、阶段实例、暂停/恢复、超时扫描和 ETA；承诺时间在下单时冻结。
4. **3.4 通知**：根据领域事件生成站内通知、模拟短信和 SSE 推送，通知失败不回滚业务事务。
5. **3.5 异常**：建立异常单、责任归属、暂停履约、人工处理和审计原因。
6. **3.6 恢复履约**：实现取消、拦截、重派、转自取、拒收和退回，并创建新的任务、运输段和 SLA 实例。
7. **3.7 阶段验收**：补齐电子面单、死信重放、正常/异常 Compose 旅程，完成阶段三验收。

## 后续阶段

- **阶段四：知识库与 RAG**。管理/运营人员从前端上传 PDF、Word、Markdown 等文档；解析、切分、向量索引和检索。RAG 只解释政策，不裁决金额、权限、状态或 SLA。
- **阶段五：AI Agent**。客户可通过对话创建地址、生成报价、确认订单、查询轨迹和处理异常。Agent 只能调用已授权业务工具，最终写入由确定性服务完成。
- **阶段六：后端收口**。冻结 OpenAPI，补齐安全、观测、性能、部署文档和前端所需契约，之后开始前端。

## 后续大模型接续规则

接手本项目时，先读取本文件、两份业务规则、`CONTEXT.md`、当前阶段计划和最新 Git 提交。不得跳过规则确认直接写价格或 SLA 代码；不得把 RAG 文档当作最终计算依据；不得修改已冻结的历史报价或 SLA 实例。
