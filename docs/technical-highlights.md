# 驿途 — 简历

## 项目简介

驿途是一个针对传统物流服务操作门槛高、人工客服响应慢，以及大模型难以可靠参与真实业务流程的痛点，利用 LangGraph、RAG 与受控工具调用技术，实现自然语言下单、查件、规则咨询的智能物流平台。

## 核心技术栈

Python、FastAPI、LangGraph、PostgreSQL / pgvector、MinerU、Qwen Embedding、Vue3、Element Plus、Celery、Redis、SQLAlchemy Async、Docker Compose

## 技术亮点

1. **基于 LangGraph 的单图工作流编排**：将寄件、查件、咨询和异常处理全部收敛到一张 StateGraph（10 节点 + 7 条条件边），路由函数与节点逻辑分离，节点只负责读输入、调能力、写回 State，条件边集中决定下一步走向。State 只存可序列化快照，身份和数据库连接通过 Runtime 机制注入不进 checkpoint，同一会话的 checkpoint 支持人工确认暂停后跨请求恢复。

2. **受控 ReAct Agent + 工具白名单**：模型只能在 6 个白名单工具中自主选择（知识检索、运单查询、地址簿、运费规则、身份读取、寄件标记），工具节点统一负责参数校验与身份注入。模型不能传入 actor_id、user_id 等信任参数，经 Pydantic 校验拒绝后服务层再次校验所有权。ReAct 循环最多 8 轮思考、4 次工具调用，工具结果截断至 8000 字符并脱敏。

3. **三阶段 RAG 混合检索**：查询先经 LLM 改写（口语化转检索关键词，超时 4s 失败回退），再以 Qwen 1024 维 Embedding 向量检索与 PostgreSQL 全文检索加权融合召回，最后用专用 cross-encoder 精排模型（gte-rerank）对 Top 30 候选重排序至 5 条，相比 LLM 精排成本更低、延迟更短。文档索引管线异步完成 MinerU 解析与 Markdown 结构化切块，法规文档做条号合并、列举项跨空行合并等特殊切块策略，版本化索引保证检索始终取最新版本。

4. **LangGraph interrupt() 人工确认**：报价生成后调用 interrupt() 暂停图执行并持久化 checkpoint，前端渲染确认卡片等待用户决策；approve 则恢复图继续建单，reject 则终止寄件流程。

5. **多层安全防护**：第一层正则安检匹配注入攻击和跨用户访问模式，命中直接拒绝不发给模型；第二层工具参数校验禁止传入信任字段；第三层确定性正则脱敏隐藏密钥、手机号、邮箱等敏感信息；第四层建单授权消费防篡改；第五层 ReAct 循环预算防无限消耗。

6. **可替换模型适配层**：通过适配器协议隔离具体云厂商 SDK，支持本地开发用的固定适配器和对接 DeepSeek 等 OpenAI 兼容服务的通用适配器。流式输出按分片拼合工具调用，内容增量实时推送，模型不支持函数调用时自动降级为 JSON 模式保持相同输出契约。

7. **短期 + 长期双轨记忆**：短期记忆取最近 20 条消息作为上下文窗口，含工具调用与观察结果；长期记忆通过向量语义召回用户偏好，向量生成失败降级为时间排序，存储前检查敏感信息。

8. **SSE 流式推送**：单次 HTTP 请求建立 SSE 长连接实时推送 token 增量，独立的消息回放端点支持断点续传，每个事件为标准 SSE 帧格式，前端通过 Fetch API 流式消费。

9. **事务性发件箱 + 领域事件**：业务事件在数据库事务内写入发件箱表，Celery Beat 定时投递，多 worker 并发安全，5 次重试后进入死信队列。

10. **行为型测试端口 + 契约冻结**：模型、知识检索、寄件编排等外部依赖全部抽象为行为型 Fake 端口（非 Mock），按预设顺序返回结果并记录完整请求用于断言，SSE 帧格式与 API 响应形状通过测试冻结防止前后端契约断裂。端到端图测试覆盖纯文本回复 → 工具调用 → 寄件暂停 → 确认恢复全链路。

11. **幂等请求 + 事务级锁**：对支付、建单等关键写操作，对请求体做稳定 JSON 编码后计算 SHA-256 指纹，借助 PostgreSQL 事务级咨询锁仲裁并发请求，相同指纹直接返回已保存响应，不同指纹的幂等键复用返回 409 防止误用。

12. **领域状态机建模**：异常工单和知识文档采用纯函数状态机，状态转换由命名动作驱动，非法转换直接拒绝，权限矩阵集中声明，与 ORM 解耦可独立单元测试。

13. **追加式审计日志**：审计记录与业务操作在同一事务内完成，记录操作前后两个 JSONB 快照，只暴露追加方法不暴露更新或删除接口，保证审计链不可篡改。

14. **工作时间日历 SLA 与自动违约检测**：SLA 按周一至周六 09:00-18:00 营业日历计算承诺时间，异常工单创建时自动暂停 SLA 并按实际耗时延长承诺，定时任务每 5 分钟自动扫描超时实例并创建异常工单。

15. **Celery-Async 桥接**：项目使用 Celery 处理异步任务（文档解析、消息推送等），但数据库操作基于 SQLAlchemy Async。由于 Celery 是同步模型，通过在 Worker 进程内维护一个共享的事件循环，让同步任务也能调用异步数据库操作，避免每次任务都新建循环的开销。
